# UI/UX review remediation

Review source: an internal UI/UX review (not published).

Findings were checked against the changing source rather than accepted from historical line numbers. This ledger distinguishes implemented source changes, automated behavior verification, visual verification, and deliberate product exceptions. Browser verification is currently blocked: the sandbox refuses Vite's listening socket (`EPERM`), and Chromium cannot launch under its macOS process restrictions. No screenshot or screen-reader pass is claimed.

## Deliberate exceptions and remaining verification

- **C4:** the historical suggestion to make Quick CSV imply Data Only conflicts with the later explicit requirement that Quick always means Structure + Data. The direct Custom/Data Only recovery removes the dead end without silently changing export semantics. Tests verify that saved Custom choices never leak into Quick.
- **H1:** retain the requested initially expanded preview and session collapse preference. Rows use 30px, rather than 26px, to accommodate the existing 14px text and accessible controls. No typography was reduced.
- **H8:** no invented storage sizes or new database drop/create/rename features. Table Operations is accessible from the database overview. Empty databases have no usable target for the prototype's limited SELECT/CSV importer, so only Structure/Export is exposed there. SQL still evaluates the documented SELECT subset; cross-table context is available but JOIN execution is not implemented.
- **H9:** Search displays at most 100 matches, with the cap disclosed only when necessary. IN/BETWEEN accept simple comma-separated values, not arbitrary SQL expressions. These are frontend predicates, not SQL execution or database collation emulation.
- **H11/M8/M15:** preserve the explicitly requested simplified Settings, schema-aware ENUM/SET badges, and allowlisted non-secret persistence. Do not modify the existing AGENTS.md. README now explains the later persistence decision.
- **M7:** index names absent from metadata are labelled unnamed/mock. Collation/comments are accessible inline details, preserving the compact grid. This mock does not discover actual server indexes, composite constraints, cascades, or deferrable constraints.
- **M14:** the explicitly requested primary-key color `#D4A017` remains below 3:1 on white. Descriptive key labels/tooltips are retained; a visually verified outline treatment is deferred rather than claiming contrast compliance. Form borders now pass ≥3:1 token checks. No screen-reader pass is claimed.
- **Browser/native checks:** Playwright was attempted again after remediation, but Vite failed to listen on `0.0.0.0:5173` with `EPERM`. Chromium/macOS native integration remains unavailable. Screenshot comparison, sticky-header pixel alignment, popover geometry, focus behavior in a real browser/webview, and responsive visual inspection remain outstanding. Authored browser assertions are not counted as passing checks.

## Architectural boundaries

`recordMutations.ts` is the common atomic constraint boundary for Insert/Edit, inline changes, bulk Copy, CSV and destructive row/schema actions. `valueValidation.ts` remains responsible for individual schema values. The mock stores single-column key/reference metadata and enforces RESTRICT; it is not a complete implementation of any database engine's transaction or constraint semantics. A future Rust/backend layer must enforce authoritative rules independently.

`browseQuery.ts`, `search.ts` and `csvImport.ts` are pure, testable adapters. Query results now belong to query tabs; explorer and pagination state belongs to connections. The shared dialog directive centralizes modal behavior without redesigning the existing dialog shells. App.vue remains large; splitting unrelated screens is intentionally outside this remediation to reduce regression risk.

No new dependency, backend connection, credential persistence, actual SQL import, or database backup was introduced.
