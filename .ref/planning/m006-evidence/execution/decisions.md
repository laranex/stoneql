## Divergences from `m006-safety-contracts.md`

1. Lease pinning uses a dedicated never-pooled connection rather than the pool's own connection (reason above); handle exclusivity and discard-always match 3-A.
2. Multi-statement scripts are included (contract 2 Phase B) rather than one statement per job.
3. Cancelled reads are not distinguished from writes: every interrupted, sent statement is `unknown` (the contract allows `rejected` for read-only). Read-only handles do not use the job path at all.
4. No `JOB_EXPIRED`, `LEASE_EXPIRED` or `TRANSACTION_ABORTED` error codes: expiry is `TransactionEnd.reason = expired`, abort is `lease = rollback_only` + `CONFLICT`; unknown/expired job ids are `FORBIDDEN`.
5. No `transaction_state`, `rollback_confirmed` or `non_transactional_effects_possible` fields; `commitSent` is on `TransactionEnd` only (job-level writes are indicated by statement `unknown`).
6. No `environment`/`acknowledge_production_write` over IPC (contract 9.3 advisory); PROD is renderer-only.
7. PostgreSQL read-write statements do not set `statement_timeout`; MariaDB `max_statement_time` is not used. Deadlines rely on the client cancel path.
8. Lost-COMMIT fault injection (contract 7.1/7.2 proxy) and SSH-routed lease/cancel cases (4.1, 5.x over SSH) are not executed; SSH read-write is gated off instead.
9. Retained-bytes-per-owner (8 MiB) is not tracked separately; per-job delivery is bounded at 4 MiB and buffered pages at 2 × 256 KiB per job.
10. Reload reporting of previous-generation outcomes (contract 4.5) is not implemented; outcomes of leases ended by reload are recorded but the new renderer session cannot query the old lease ids.
11. The duplicated 3600 s handle lifetime (desktop `lib.rs` and `database.rs` reply) is not unified (not touched).

## Safety-fix pass additions (2026-10-26; implemented, uncommitted, awaiting review — none approved)

- **Native read-write gate:** `READ_WRITE_SQL_ENABLED = false` in the desktop host (`HostServices.read_write_sql`), reported as `HostInfo.readWriteSql`; `access: read_write` refused (`UNSUPPORTED_CAPABILITY`) before Keychain or network; only `app_builder_with` (tests) can enable it.
- **Recorded ends:** `TransactionEnd.rollbackSent` added (contract, required). `unknown` recorded at lease removal and before COMMIT/ROLLBACK is sent; upsert by lease id; every later `end_transaction` returns the record (no FIFO removal on read; still capped at 32).
- **MySQL/MariaDB COMMIT refused with a database error → `unknown`** (`commitSent=true`), no ROLLBACK claim (L-7).
- **Statement policy:** whole-statement `autocommit` scan for `SET` (incl. quoted identifiers), refusal of MySQL/MariaDB `PREPARE`/`EXECUTE`/`DEALLOCATE`/`DROP PREPARE`, refusal of custom-DELIMITER statements containing a further statement outside `BEGIN … END`, `BACKUP` added to the in-lease implicit-commit list.
- **Close ordering:** disconnect and handle expiry remove the handle before releasing work; submit/begin re-check after registering; a job interrupted before opening never opens.
- **Renderer:** 20 s wait for `end_transaction`/`disconnect_database`; commit timeout reported as "commit outcome unknown"; disconnect with an open lease confirms and shows the recorded outcome.

## R-1..R-3 fix pass additions (2026-10-29; implemented, uncommitted, awaiting review — none approved)

User-approved principles applied (2026-10-26): never claim committed/rolled back without server confirmation; uncertain = unknown; never auto-retry; do not weaken checks. Read-write stays gated OFF.

| Finding | Choice | Why this option |
| --- | --- | --- |
| R-1 SQLite multi-statement smuggling | `execution.rs::sqlite_single_statement`: before each SQLite statement is sent, every prefix ending at a `;` (with text after it) is prepared on the job's connection; the statement runs only if every prefix fails with a parse error that depends on the text alone (`incomplete input`, `unrecognized token:`, `…: syntax error`). Anything else (a prefix that prepares, a schema error, NUL, more than 256 `;`) → statement `failed`, nothing sent. Splitter: SQLite trigger bodies end only at `; END ;` (SQLite grammar / `sqlite3_complete`), vertical tab is whitespace. | The workspace forbids `unsafe`, so SQLite's own `pzTail` (FFI) is unavailable; SQLx exposes no statement count. Prefix prepares use SQLite's real tokenizer and parser without executing, and acceptance is schema-independent, so a later schema change cannot turn a rejected prefix into a statement end. Conservative cost: a `;` inside a comment refuses the statement. |
| R-2 MariaDB wrappers / compound statements | In-lease leading-keyword **allow-list** (SELECT, WITH, VALUES, TABLE, SHOW, DESCRIBE/DESC, EXPLAIN, INSERT, UPDATE, DELETE, REPLACE, USE, CREATE/DROP TEMPORARY TABLE, `SET @user` only; no `;` anywhere). `SET STATEMENT … FOR` refused entirely; statements starting with CASE/IF/LOOP/WHILE/REPEAT/FOR or a label refused; `CALL` refused; all in and out of a lease. New `ScriptError` variants `NotAllowedInTransaction` (replaces `ImplicitCommitInTransaction`), `SetStatement`, `CompoundStatement`, `Call` (all map to `UNSUPPORTED_SQL`; no DTO change). | Allow-list instead of a growing deny-list; `SET STATEMENT` refusal is the simplest acceptable option named by the user. `USE` was added to the allow-list because the fixture's session-state cycles use it inside a lease and it has no transactional effect. |
| R-3 server-side state | Option (a)+(b): refuse MySQL/MariaDB `CALL`, **and** check the session after every job (`Physical::state_matches`; MySQL/MariaDB `pub fn mysql_state_matches`: `SELECT CAST(@@autocommit AS SIGNED)` = 1 outside a lease, `SET TRANSACTION READ WRITE` → ER 1568 exactly while a transaction is active; SQLite `BEGIN` → "within a transaction" error inside, success + ROLLBACK outside; 2 s bound). Mismatch/error/timeout → job `unknown`; in a lease `diverged` → rollback-only, end sends neither COMMIT nor ROLLBACK, `unknown`. UI: "(autocommit)" instead of "(committed)"; "COMMIT/ROLLBACK may have been sent". | No vendor change (D002); the probe needs no privileges (`performance_schema`/`information_schema.innodb_trx` need grants and InnoDB starts transactions lazily). MariaDB `@@in_transaction` would work there only; one probe for both engines. `CALL` refusal stays because a procedure can also run dynamic SQL the policy cannot see. The end is not re-probed: nothing runs on a lease session between a job's check and COMMIT/ROLLBACK, and a probe there would become the first statement a lost reply hits (the B-4 relay evidence depends on COMMIT being that statement). PostgreSQL is not probed (procedures/DO cannot end a transaction block; one statement per Parse). |

Known conservative effects: a MySQL deadlock (ER 1213) inside a lease is reported diverged/`unknown` though the server rolled it back; `failed` for a refused SQLite statement is shown as "the database rejected statement N" (no new DTO field). Residual: outside a lease, a MySQL routine-DDL statement whose BEGIN … END nesting the splitter misjudges could reach the 1295 text fallback; the prepared protocol rejects multi-statement text first (ER 1064, checked on both servers) and any transaction state left behind is caught by the session check.
